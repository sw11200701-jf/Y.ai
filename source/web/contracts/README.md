# Shared contract v1.0.1 — READY

Current additive platform contract: **2.0.0 READY**, see [workflow-v2.md](workflow-v2.md), generated node-registry.json and workflow.schema.json. This document preserves the compatible1.0.1 surface below; /api/v1 prefix remains. Missing schemaVersion runs legacy1.0;2.0 enables DAG/variables/branches/repetition. Actual live status comes from /api/v1/workflows/node-registry, not from this historical route table.

Frozen 2026-10-15 (Asia/Shanghai). API prefix `/api/v1`; JSON field names snake_case. Public shared files are owned by engineering. Request changes in `docs/coordination/dependency-requests.md`; do not edit shared models or entry points in module tasks.

Canonical executable types: `services/api/app/contracts.py`. OpenAPI is generated by FastAPI at `/openapi.json` and checked into `contracts/openapi.json` by `scripts/export_openapi.py` after integration. Workflow schema: `workflow.schema.json`; service signatures: `service-interfaces.md`.

All amounts and ratios are decimal strings (never JSON floats). Dates use ISO-8601 UTC; IDs are strings. Synthetic data must carry `synthetic=true` and source references. Lists return `{items:[...]}`. Errors return `{error:{code,message,details},request_id}`. BusinessContext is injected by the server; model/business input cannot override tenant/workspace/operator.

Node types: start, plugin, query, calculate, chart, report, end. Legal graphs are connected linear chains with exactly one start/end, no cycles, no extra edges. Node input references only use explicit previous results, no arbitrary code or shell execution.

Error codes: VALIDATION_ERROR (422), NOT_FOUND (404), CONFLICT (409), INVALID_WORKFLOW (422), INVALID_BINDING (422), TOOL_ERROR (502), TOOL_TIMEOUT (504), CONNECTION_BLOCKED (403), IMPORT_INVALID (422), FINANCIAL_CONTEXT_MISMATCH (422), MISSING_FACT (422), ZERO_DENOMINATOR (422), QUEUE_FULL (429), RUN_TIMEOUT (504), CANCELLED (409), SERVICE_UNAVAILABLE (503), INTERNAL_ERROR (500). Financial services may emit missing/zero warnings in ResultDataset rather than fail a whole report, with no silent zero fill.
